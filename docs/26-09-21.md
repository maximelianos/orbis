# Trajectory diffusion: bugs found and fixed on 2026-09-21

Written 2026-09-21. Review of the training code in
[exp_navsim/](../exp_navsim/), the basic model and the world-model variant in
[exp_navsim/wm/](../exp_navsim/wm/). The flow-matching schedule itself was
correct. Everything below is either a bug in how batches are handled or a knob
that slows convergence down.

Old checkpoints do not load after these fixes. The aggregator input width, the
embedding MLPs and the output layer init all changed, so both models have to be
retrained.

Fixed:
1. The frame number embedding depended on the rest of the batch
2. The diffusion time embedding barely moved
3. Long episodes dominated the loss




## Fixed

### 1. The frame embedding depended on the rest of the batch (very important)

The frame position was embedded as `arange(T) / T`, where `T` is the padded
length of the batch, not the length of the episode. So frame 5 of one episode
got a different embedding depending on which episodes happened to be collated
next to it, and the image aggregator inherited the same drift through its AdaLN
condition. Both denoisers now index an absolute frame table built once in
[embeddings.py](../exp_navsim/embeddings.py).

### 2. Attention read the padding (actually important)

The loss mask kept padded frames out of the loss, but nothing kept them out of
the attention, so every real frame was reading zero-padded noise whose amount
changed from batch to batch. The denoisers now take a `frame_mask` and pass a
`key_padding_mask` down to `nn.MultiheadAttention`
([networks/blocks.py](../networks/blocks.py) got an optional argument, default
`None`, so the other experiments are untouched). An image token is masked
exactly when its own frame is.

Noising is applied to padding too - the padding is not just zeros.

### 3. The diffusion time embedding barely moved (very important)

The sin-cos basis in [dit.py](../networks/DiT/dit.py) spans four decades of
frequency, and `t` lives in `[0, 1]`, so every band except the highest stayed
almost constant and most of the 64 dimensions carried nothing about `t`. The WM
denoiser already multiplied by 1000 before the basis, the basic one did not.
Both now use the same helper with the same spread.

### 4. Frame 0 was scored

Velocity is a finite difference and `v_0` is defined as 0 for every episode, so
scoring it hands the model a free constant and pulls the EMA velocity mean
toward zero. In the trajectory metrics it is worse than useless, since frame 0
is the origin of the prediction and of the ground truth by construction. There
are now two masks in [model.py](../exp_navsim/model.py): `frame_mask` for what
exists, `scored_mask` for what counts. Frame 0 stays in the input.

### 5. The position embedding cache never hit

In [pos_emb.py](../networks/pos_emb.py) `PositionEmbedding2d` wrote `self.pos_embed` while testing
`self.pos_embed_2d`, so the branch was always taken and every `SpatialBlock`
call rebuilt the H×W table in numpy, on the CPU, with a device sync each time.
That is 50 sampling steps times 20 validation samples of avoidable work. The
buffer now matches the check, and the M query vectors of `SpatialBlock` are
built once at init the way DiT builds its `pos_embed`.

### 6. Long episodes dominated the loss

The loss pooled every valid frame of the batch into one average, so an episode
contributed in proportion to its length. NAVSIM scenes run from 5 to about 40
frames, which means a long episode counted eight times as much as a short one
and the gradient followed whatever the longest episodes were doing. The loss now
averages inside each episode first and then over episodes, so every episode is
one vote. `val/mse` had the same bias and got the same treatment, and both go
through one helper in [metrics.py](../exp_navsim/metrics.py) so they cannot
drift apart.

### 7. Uniform timestep sampling

The training timestep was drawn uniformly from `[0, 1)`, which spends the same
effort on every part of the schedule. The ends are the easy part, since near
`t = 0` the input is almost the clean trajectory and near `t = 1` it is almost
pure noise, and the middle is where the shape of the trajectory is actually
decided. Training now draws `t = sigmoid(u)` with `u` standard normal, the
logit-normal schedule from SD3, which concentrates samples around `t = 0.5`. The
sampling ODE at inference is unchanged.

### Two changes that were not bugs

The aggregator now reads both cached latents, `q_sem` and `q_rec` concatenated
over channels, instead of throwing the reconstruction latent away after loading
it from disk. And the output layer of the basic denoiser is zero-initialised,
so training starts from a zero velocity field, which is what the WM denoiser and
DiT both already did.

## Not fixed

### The world-model run never validates

With `batch_size: 16` and `dataset_length: 100000`, one epoch is 6250 steps, so
`check_val_every_n_epoch: 5` puts the first validation at step 31250 while the
run stops at 20000. The basic config validates 4 times in a whole run, which is
not enough to see anything. Use `val_check_interval` in steps instead.

### The buffer serves the same 100 episodes at the start

[buffer.py](../exp_navsim/data/buffer.py) starts with 100 samples and adds about
25 per batch of 100, so the first several hundred steps see a tiny, repeated
subset, and `_source_idx` walks the files in sorted order, which puts episodes
from the same log next to each other. Reading two latent frames from an h5 file
is cheap enough that the buffer buys nothing here. Loading the whole split into
RAM, around 65 KB per episode, and raising `num_workers` would be simpler and
more random.

### There is no augmentation

`num_frames: 0` means the window is the whole episode, so the start is always 0
and every episode produces exactly one sample, every epoch, forever. Random
fixed-length windows would give roughly 30 times more distinct samples from the
same cache, and they would also make the padding problems above disappear.

### No EMA of the weights

Diffusion models are usually evaluated with an exponential moving average of the
weights, and the gap is large enough that `val/mse` without it understates what
the model can do. Nothing in the pipeline keeps one.

### Optimiser settings

The basic config has no warmup and `gradient_clip_val` is unset, and the
checkpoint callback monitors `train/loss`, which is a noisy quantity because the
diffusion timestep is resampled every step. Monitoring `val/mse` would pick
better checkpoints. Warmup matters more now that the output layer starts at
zero.

### The imagined latent is stochastic, and recomputed every step

`_denoise_next` in [wm_runner.py](../exp_navsim/wm/wm_runner.py) starts from
`randn`, so the imagined latent changes at every training step even though the
world model is frozen, and the docstring claiming it is deterministic is wrong.
Validation memoises it per batch but does not seed it, so val numbers wobble
between runs. Since the conditioning context is always frames 0 and 1, the
imagined latent could be computed once offline and cached, which would remove
four 700M-parameter forward passes from every training step and let the WM run
use the same batch size as the basic one.

### The two runs are not comparable step for step

The WM config trains at batch 16 against the basic model's 100 with the same
learning rate and the same step count, so after 20000 steps it has seen about
six times less data. Either match the effective batch size or compare on samples
seen rather than on steps.

### EMA velocity statistics are per rank

[norm.py](../exp_navsim/norm.py) updates its mean and variance from the local
batch and never syncs them, so multi-GPU runs normalise slightly differently on
each rank. It does not matter on one GPU. Precomputed dataset statistics would
remove the whole question.
